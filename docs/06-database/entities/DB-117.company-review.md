# DB-117 — CompanyReview

## 1. Objetivo

`CompanyReview` representa uma avaliação realizada por um usuário sobre uma empresa cadastrada no Bairu.

A entidade permite que a comunidade registre sua experiência com negócios locais e contribui para a construção de confiança na plataforma.

---

## 2. Responsabilidade

`CompanyReview` é responsável por:

- registrar a avaliação de uma empresa;
- identificar o usuário responsável pela avaliação;
- armazenar a nota atribuída;
- armazenar o comentário, quando fornecido;
- controlar a criação da avaliação;
- servir como fonte da verdade para indicadores derivados da reputação da empresa.

A entidade não é responsável por:

- moderação de conteúdo;
- denúncias;
- respostas da empresa;
- mecanismos de reputação avançados.

Essas funcionalidades poderão ser avaliadas futuramente.

---

## 3. Estrutura

Campos previstos para o MVP:

| Campo        | Tipo        | Obrigatório | Descrição                        |
| ------------ | ----------- | ----------: | -------------------------------- |
| `id`         | UUID        |         Sim | Identificador da avaliação       |
| `user_id`    | UUID        |         Sim | Usuário que realizou a avaliação |
| `company_id` | UUID        |         Sim | Empresa avaliada                 |
| `rating`     | SMALLINT    |         Sim | Nota atribuída à empresa         |
| `comment`    | TEXT        |         Não | Comentário associado à avaliação |
| `created_at` | TIMESTAMPTZ |         Sim | Momento da criação               |
| `updated_at` | TIMESTAMPTZ |         Sim | Momento da última alteração      |

`updated_at` é utilizado porque o usuário poderá alterar sua própria avaliação.

---

## 4. Relacionamentos

```text id="h4y1xj"
User
  │
  │ 1:N
  ▼
CompanyReview
  │
  │ N:1
  ▼
Company
```

Um usuário pode avaliar várias empresas.

Uma empresa pode receber avaliações de vários usuários.

Cada avaliação pertence a exatamente um usuário e uma empresa.

---

## 5. Unicidade

No MVP, um usuário poderá possuir **uma avaliação ativa por empresa**.

A combinação:

```text id="0k5f0n"
(user_id, company_id)
```

deve possuir constraint `UNIQUE`.

Exemplo:

```text id="6ozc8w"
UNIQUE (user_id, company_id)
```

Caso a avaliação seja removida, o usuário poderá criar uma nova avaliação para a empresa.

Essa regra mantém o modelo simples e evita múltiplas avaliações simultâneas do mesmo usuário para a mesma empresa.

---

## 6. Rating

`rating` representa a nota atribuída pelo usuário.

No MVP, a escala será de:

```text id="r4i6pv"
1 → 5
```

Valores fora desse intervalo não devem ser aceitos.

A restrição deve ser garantida pelo banco por meio de `CHECK`.

Exemplo:

```
CHECK (rating >= 1 AND rating <= 5)
```

A aplicação também deve validar o valor recebido antes da persistência.

---

## 7. Criação e Alteração

A criação de uma avaliação exige:

- usuário autenticado;
- empresa existente;
- usuário autorizado a realizar a operação;
- inexistência de avaliação ativa do usuário para a empresa;
- nota dentro do intervalo permitido.

O usuário poderá alterar sua própria avaliação.

Exemplo:

```text id="s6qv6h"
User
  ↓
Create Review
  ↓
CompanyReview
```

ou:

```text id="v8s1iy"
Existing Review
  ↓
User edits
  ↓
Updated Review
```

Um usuário não deve poder alterar ou excluir a avaliação pertencente a outro usuário.

---

## 8. Comentário

O comentário é opcional.

A ausência de comentário não impede a criação da avaliação.

Isso permite avaliações baseadas apenas em nota:

```text id="c6kj8q"
Rating: 5
Comment: null
```

ou avaliações acompanhadas de uma experiência textual:

```text id="r8s2ki"
Rating: 5
Comment: "Excelente atendimento."
```

Regras mais avançadas de moderação ou filtragem de conteúdo não fazem parte do MVP.

---

## 9. Exclusão

`CompanyReview` utilizará Hard Delete no MVP.

A remoção da avaliação elimina o relacionamento entre o usuário e a empresa.

```text id="yq7kq4"
CompanyReview
      ↓
Hard Delete
```

A exclusão não deve remover:

- o usuário;
- a empresa;
- outras avaliações.

Quando a empresa ou o usuário forem removidos, suas avaliações deverão seguir a estratégia de exclusão definida para os relacionamentos da plataforma.

---

## 10. Dados Derivados

`CompanyReview` é a fonte da verdade para os indicadores de avaliação da empresa.

Caso utilizados, os seguintes campos em `Company` serão considerados dados derivados:

```
Company.rating_average
Company.rating_count
```

A relação é:

```
CompanyReview
      ↓
fonte da verdade
      ↓
Company.rating_average
Company.rating_count
```

Os indicadores devem poder ser recalculados a partir das avaliações existentes.

A existência desses campos na entidade `Company` depende da necessidade real de desempenho.

---

## 11. Atualização dos Indicadores

Quando uma avaliação for:

- criada;
- alterada;
- removida;

os indicadores derivados da empresa deverão ser atualizados incrementalmente ou recalculados integralmente

Sempre que possível, a alteração da avaliação e a atualização dos indicadores devem ocorrer na mesma transação do banco.

Exemplo:

```text
CompanyReview
      │
      ├── create/update/delete
      │
      └── update Company indicators
```

A implementação deve preservar a capacidade de reconstruir os indicadores a partir da fonte da verdade.

---

## 12. Integridade Referencial

As Foreign Keys devem garantir que:

```text id="d3h8l5"
CompanyReview.user_id
        ↓
User.id
```

e:

```text id="6q8g5u"
CompanyReview.company_id
        ↓
Company.id
```

sempre apontem para registros válidos.

A estratégia de exclusão dos registros relacionados deve seguir as convenções gerais de lifecycle e integridade do banco.

---

## 13. Índices

Índices previstos:

```
idx_company_reviews_company_id
```

para recuperação das avaliações de uma empresa.

`idx_company_reviews_created_at`
para ordenação cronológica das avaliações.

A constraint:
`UNIQUE (user_id, company_id)`
garante a unicidade da avaliação por usuário e empresa e também suporta consultas utilizando essa combinação.

O desenho definitivo dos índices deverá ser validado conforme os padrões reais de consulta da aplicação.

---

## 14. Decisões Importantes

| Decisão                                | Justificativa                                                 |
| -------------------------------------- | ------------------------------------------------------------- |
| `CompanyReview` é uma entidade própria | Representa uma relação com regras e dados próprios            |
| Uma avaliação por usuário/empresa      | Evita avaliações duplicadas simultaneamente                   |
| Rating de 1 a 5                        | Modelo simples e familiar para o MVP                          |
| Comentário opcional                    | Permite avaliar sem exigir texto                              |
| Usuário pode editar sua avaliação      | Permite corrigir ou atualizar sua experiência                 |
| Hard Delete                            | A avaliação removida deixa de fazer parte da fonte da verdade |
| `CompanyReview` é fonte da verdade     | Permite derivar indicadores de reputação                      |
| Sem moderação complexa no MVP          | Evita antecipar infraestrutura ainda não necessária           |
| Sem resposta da empresa no MVP         | Mantém o escopo inicial simples                               |
